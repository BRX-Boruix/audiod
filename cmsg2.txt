M2: f32 混音核心（N 路相加 + 固定增益 + 饱和钳位）

【实现】新增 src/lib.rs（#![no_std] 纯逻辑库，模式同 intel-hda）：
  - s16/u8/s24 -> f32 转换；
  - mono -> stereo 直接复制（不做 pan 衰减）；
  - mix_add：逐样本相加、乘 1/N、clamp(-1,1)、f32 -> s16 饱和转换。

单独成库的理由（S23/S29）：这些是**纯函数**，隔离后可在宿主穷举验证
（如 s16->f32 的 65536 个输入单调性），无需 QEMU 与真实设备。
若混在裸机 bin 里，唯一手段是"跑一遍看打印"，既慢又覆盖不到边界。

【增益取 1/N 而非 1/sqrt(N)，理由是保证是无条件的】
1/sqrt(N) 只约束**平均功率**：N 路相关信号（都放同一个音，正是硬件测试
的情形）相加仍会削波，于是削波成为常态而非兜底。1/N 则因 |x|<=1 蕴含
|sum/n|<=1，**永不越界**。代价是非相关素材偏轻——那是可逆的音量选择，
而削波是烘进输出的失真。

【修正一处我自己的算错（测试抓出来的）】
两路验证信号初版取 +16384 与 -16383（幅度仅差 1），二者**几乎完全相消**
（和仅 1/65536），输出近似静音——既证明不了相加，也与"无数据"无法区分。
测试首次运行即失败并给出实测值 0.000015258789，据此改为 +24576 / -8192
（幅度差 3 倍），预期输出 +0.25 -> s16 约 8192。

【测试有牙（变异验证）】故意注入 3 个典型错误，确认每个都被抓住：
  1/n -> 1/sqrt(n)                 -> 1 failed ✓
  s16 用 32767 而非 32768          -> 1 failed ✓
  mono 复制时误加 0.5 衰减          -> 1 failed ✓
宿主测试 **8 PASS**。

【端到端实测（QEMU pc + intel-hda + hda-output）】
两路：stream/0 写 +24576，stream/1 写 -8192：
  [audiod] mixed ... live_inputs=2
  [intel-hda] A3 dump +0000: ff 1f ff 1f ...   = 0x1fff = 8191
预测 trunc(((24576/32768) + (-8192/32768)) * 0.5 * 32767) = 8191，**逐位吻合**。
其余三种失败模式各有明确不同取值（仅 A -> 24575、仅 B -> -8192、
都没有 -> 无字节写出），均被排除。
